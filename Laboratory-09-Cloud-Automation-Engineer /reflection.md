# Mission Reflection

During Laboratory 9, I learned how automation can help manage cloud systems more efficiently. A Bash script allows several commands to run together, while Cron can schedule those commands to run automatically. I created a sample application folder, wrote a backup script, gave it executable permission, and tested whether it could produce a compressed backup file.

Automation is important when managing hundreds of cloud servers because doing every task manually takes a lot of time. Automated scripts can perform repetitive tasks consistently and reduce human errors. They also allow IT staff to focus on monitoring, troubleshooting, and improving systems instead of repeating the same commands.

However, automation also has risks. If a script contains a destructive command or an incorrect path, it could delete or damage important files. If the same mistake runs on 1,000 servers, the damage could affect many systems. For this reason, scripts should be reviewed, tested in a safe environment, and monitored before they are used on production servers.

Writing a Bash script was different from creating a Docker Compose YAML file in Mission 6. Bash uses commands and variables to perform tasks step by step. Docker Compose YAML describes services, configurations, networks, and other settings used to run containers. Both are useful tools, but they solve different problems.

From Laboratory 1 to Laboratory 9, my understanding of cloud computing developed from learning basic cloud concepts to working with infrastructure, deployment, operations, security, and automation. I learned that cloud computing involves more than storing files online. It also requires managing resources, protecting systems, and making services reliable.

The role I enjoyed most was the Cloud Automation Engineer because I liked learning how to automate repetitive tasks. This activity showed me how a simple script and a scheduled task can help make system administration more organized and efficient.
